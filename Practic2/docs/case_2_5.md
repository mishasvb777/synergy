# Кейс-задача 2.5 — Предложения по улучшению решения кейса 2.3

На основе анализа реализации выявлены потенциальные проблемы и предложены пути решения.

## 1) Ограниченная модель данных

**Проблема:** хранится только год приема, что делает стаж приблизительным.  
**Решение:** перейти к полной дате приема (`dd.mm.yyyy`) и считать стаж с учетом месяца и дня.

## 2) Валидация пользовательского ввода

**Проблема:** базовые проверки есть, но они не охватывают все ошибки формата.  
**Решение:** добавить:

- проверку на пустые строки ФИО и должности;
- проверку диапазона зарплаты с учетом бизнес-ограничений;
- отдельные функции нормализации и валидации строк.

## 3) Масштабируемость приложения

**Проблема:** логика ввода, вычислений и отображения сосредоточена в `cmd/worker_app/main.go`.  
**Решение:** разделить на слои:

- `WorkerService` для бизнес-правил;
- `ConsoleUI` для взаимодействия с пользователем;
- `WorkerRepository` для хранения/загрузки данных.

## 4) Недостаточная автоматизация тестирования

**Проблема:** есть базовые тесты, но пока нет сценариев на пользовательский ввод и тестов уровня интеграции.  
**Решение:** расширить покрытие и добавить автоматический запуск `go test ./...` в pipeline (например, GitHub Actions).

## 5) Отсутствие постоянного хранения данных

**Проблема:** после завершения программы данные теряются.  
**Решение:** добавить сохранение и загрузку списка сотрудников в файл (`json`/`csv`) или БД.

## 6) Отсутствие расширенной аналитики

**Проблема:** приложение выполняет только фильтрацию по стажу.  
**Решение:** реализовать дополнительные отчеты:

- средняя зарплата по должностям;
- распределение сотрудников по стажу;
- поиск и сортировка по нескольким критериям.
